PMM-15663 · node and service annotations

How an annotation reaches a dashboard: before, after PMM-15609, and with PMM-15663

Are these annotations coming from Grafana? They are stored in Grafana, the same as always. With PMM-15663, the markers for node and service annotations are drawn from a copy that pmm-managed writes to VictoriaMetrics. Only global markers are still drawn straight from Grafana.

That copy is why the markers work on All and respect LBAC, and also why Grafana doesn't know their ID.

Grafana annotation store VictoriaMetrics Works Broken or missing

1. Before PMM-15609

main today
  • AddAnnotation creates one Grafana annotation tagged with the node name or the service names. A global annotation gets the tag pmm_annotation.
  • Each dashboard asks Grafana for annotations tagged pmm_annotation or the selected node or service. On All, every name is sent as a tag.
  • The markers come from Grafana, so they carry their ID and Edit and Delete work. But the request grows with the fleet, which is what PMM-15609 set out to fix.

Source: the dashboard definitions on main and the description of PR #6045. I didn't re-run this stage live.

2. After PMM-15609

PR #6045, open: the bug in PMM-15663
  • PMM-15609 sets All to .+ on fleet-sized variables so every request stays small.
  • On All, the dashboard asks Grafana for the tags pmm_annotation and .+. Only global annotations match, so node and service markers disappear.
  • A selected node or service still works, because then its real name is sent.

Reproduced live on the test VM: on All, Home, Nodes Overview and MySQL Instances Overview returned only the global annotation.

3. With PMM-15663

PMM-15663-scoped-annotations
  • AddAnnotation still creates the Grafana annotation first (step 1). It then writes one pmm_annotation_event series per node or service to VictoriaMetrics, carrying the annotation’s ID, text, tags and that object’s labels (step 2).
  • The sync job runs on the leader at start-up and every 5 minutes. It writes series that are missing (after an upgrade, or when VictoriaMetrics was down) and deletes series whose Grafana annotation is gone.
  • Dashboards now have two annotation queries: global ones from Grafana as before, and node and service ones from VictoriaMetrics through vmproxy, so a restricted role sees only the annotations of what it may see.

Verified live on the test VM: shown on All, scoped when one object is selected, LBAC with an environment role and a custom-label role, backfill of annotations made before the upgrade, and all three delete paths below.

Why the node and service marker has no ID

  • Grafana resolves DELETE /api/annotations/undefined by looking up annotation “undefined”. The lookup fails, and Grafana reports every failed lookup as “You'll need additional permissions… annotations:delete”. No permission changes that; Admin already has them all.
  • No dashboard or query setting can pass the ID through. Hiding or fixing these buttons needs a change in Grafana’s code, which we don’t want to make.
  • Tested on the test VM only: a short rule in PMM’s nginx can answer that request with a message saying how to delete the annotation, instead of the permissions error.
