# Percona Monitoring and Management 3.10.0
**Release date**: 22 October 2026

Percona Monitoring and Management (PMM) is an open source database monitoring, management, and observability solution for MySQL, PostgreSQL, MongoDB, Valkey and Redis. PMM empowers you to:

- monitor the health and performance of your database systems
- identify patterns and trends in database behavior
- diagnose and resolve issues faster with actionable insights
- manage databases across on-premises, cloud, and hybrid environments

## 📋 Release summary

PMM 3.10.0 makes PMM HA Cluster generally available with OpenShift support, in-place upgrades, backup and restore. It also adds the first database management Apps, native ARM64 support for PMM Server, MySQL 9.7 support, and a new MongoDB Unused Indexes dashboard.

This release also includes security fixes, multiple improvements, and bug fixes across all deployments.

### PMM HA Cluster is now generally available

PMM 3.10.0 completes the HA Tech Preview introduced in PMM 3.6.0 with the features and improvements needed to run HA reliably in production:

- [Backup and restore](../install-pmm/backup-restore-HA-clustered.md) for your entire HA installation to S3-compatible storage or a shared volume, on demand or on a schedule. Restore into the same cluster or a new namespace for disaster recovery.
- [Built-in alert rules](../alert/templates_list.md#pmm_ha_alerts) for no active leader, split-brain, leader flapping, unreachable nodes, quorum at risk, and persistent volumes over 80% full.
- OpenShift support for versions 4.19 to 4.22, including ROSA with hosted control planes, alongside Amazon EKS 1.33 to 1.36. [Check which platform versions each Helm chart version supports](../install-pmm/HA-clustered.md#check-if-your-platform-is-supported).
- [In-place Helm upgrades](../pmm-upgrade/upgrade_helm_ha.md) with a single `helm upgrade` command, supported starting with PMM 3.10.0 and `percona/pmm-ha` chart 1.8.0. PMM Server replicas restart one at a time, so monitoring is only briefly interrupted while a new leader takes over.
- [Flexible scaling](../install-pmm/install-HA-clustered.md#scale-pmm-server-replicas) to 1, 3, or 5 PMM Server replicas, with Helm validation that rejects even counts.
- [Multi-namespace deployments](../install-pmm/install-HA-clustered.md#install-pmm-ha-into-multiple-namespaces) on the same cluster.
- Multiple [fixes](#fixed-issues-ha) and [improvements](#improvements-ha) for HA Cluster.

- Improved [PMM HA Health Overview](../reference/dashboards/dashboard-ha-health-overview.md) dashboard with alive and expected instance counts, leader and primary roles, and resource usage panels:

![PMM HA Health Overview dashboard](../images/PMM_HA_Health_Overview.png)

For help with lost Raft quorum, leader election problems, and component logs, [troubleshoot PMM HA Cluster issues](../troubleshoot/ha_issues.md).

### Built-in alerts for PMM's own components

PMM monitors its own components and alerts you when one stops responding, so you can act before gaps appear in your monitoring data. Four [built-in alert rules](../alert/templates_list.md#pmm_component_alerts) warn you when:

- **VictoriaMetrics** components fail, to avoid gaps in your metrics
- **ClickHouse** is down, to protect your Query Analytics (QAN) data
- **Grafana** instances fail in a PMM HA Cluster, to keep your dashboards available
- **Query Analytics API** is down, to make sure QAN stays up-to-date

The new rules are turned on automatically on every PMM Server, including when you upgrade.

To get started, [configure a contact point](../alert/contact_points.md) and [customize the rules or turn them off](../alert/built_in_alerts.md).

### Database management apps: MySQL Backups and Support diagnostics

!!! warning "Tech Preview"
    This feature is not production-ready. Use for testing and feedback only.

PMM has always been about monitoring your databases. Now, it enables you to manage them too. This release introduces PMM's first database management apps, letting you run operations on your hosts directly from PMM, without SSH access.

With this initial integration, you can run MySQL backups and send diagnostic results to your Percona Support case. Both apps are available under **Apps** in the sidebar. More apps will follow in future releases.

#### MySQL Backups

Schedule and run MySQL backups for services in your PMM inventory using XtraBackup, Mydumper, or Binlog, restore from any saved backup, and track job status, backup type, and execution history.

This app runs alongside the existing MySQL backup feature in **Backups > All backups** and is intended to replace it in a future release. Backups made in one do not appear in the other.

![Management MySQL Backup screen](../images/apps_mysql_backups.png)

#### Support diagnostics

Run targeted diagnostic scripts on your monitored hosts and send the results directly to your Percona Support case in ServiceNow, without SSH access or manual file uploads.

![Management Support Diagnostics screen](../images/apps-support_diagnostics.png)

To get started, [set up Apps](../apps/deploy-pmm-extensions.md) to enable the new **Apps** menu. For programmatic access, see the [Apps API](https://percona-pmm.readme.io/reference/extensions-tasks-overview).

### MongoDB Unused Indexes dashboard

Go to **Dashboards > MongoDB > [MongoDB Unused Indexes](../reference/dashboards/dashboard-mongodb-unused-indexes.md)** to spot unused indexes directly in PMM, without running manual queries against each node. The dashboard shows indexes with zero accesses since the last `mongod` restart, along with access trends and a least-used index ranking across clusters, replica sets, nodes, and databases. Requires the `indexstats` collector on the MongoDB exporter.

### Override alert thresholds for individual nodes

If you have the PMM **Admin** role, you can now set a custom alert threshold for a specific node without editing the alert rule or creating a new one. One rule still covers all nodes, but each node can use its own sensitivity. A node with an override uses its own threshold, and the others keep the rule's default.

Templates that support overrides show a **Dynamic** badge in **Alerts > Templates**. Currently, only the built-in [Node high CPU load](../alert/templates_list.md#os_alerts) template supports this, but you can add override support to your own custom templates. More built-in templates will support overrides in future releases.

To get started, see [Override alert thresholds for individual nodes](../alert/alert-thresholds.md).

### Environment filter for MySQL Replication Summary

The [MySQL Replication Summary](../reference/dashboards/dashboard-mysql-replication-summary.md) dashboard now includes an **Environment** filter, consistent with other PMM dashboards. Use it to quickly narrow replication data to a specific environment when working with a large number of replication sets across multiple environments.

![Environment filter on MySQL Replication Summary dashboard](../images/env_filter.png)

### MySQL 9.7 support and monitoring improvements

PMM 3.10.0 adds support for Oracle MySQL 9.7 and Percona Server 9.7 with changes that also improve MySQL 8.0 and newer monitoring:

- **Service Summary reports** now work on MySQL 9.x hosts where `mysqldump` is not installed.
- **InnoDB redo log panels** in [MySQL InnoDB Details](../reference/dashboards/dashboard-mysql-innodb-details.md) now render correctly across all supported MySQL versions, including MySQL 5.7, Percona Server 5.7, and MariaDB.
- The [InnoDB redo log sizing advisor](../advisors/checks/innodb_redo_logs_not_sized_correctly.md) now correctly evaluates redo log capacity on MySQL 8.0.30 and newer.
- **Backups of MySQL 9.7** are no longer rejected with an incompatible-XtraBackup error. Use a Percona XtraBackup release from the same series as your server, for example PXB 9.7.x for MySQL 9.7.x.
- **Top Tables by Rows Read** and **Top Tables by Rows Changed** in [MySQL Table Details](../reference/dashboards/dashboard-mysql-table-details.md) now show data on Community MySQL.
- **AHI Miss Ratio** in [MySQL InnoDB Details](../reference/dashboards/dashboard-mysql-innodb-details.md) now correctly shows the miss ratio on short time ranges.
- **Query Cache panels** across [MySQL Instances Overview](../reference/dashboards/dashboard-mysql-instances-overview.md) and [MySQL Instance Summary](../reference/dashboards/dashboard-mysql-instance-summary.md) now show a notice on MySQL 8.0 and newer instead of silently showing no data.

#### Changes to be aware of

- The Checkpoint Age limit series is now labeled **Redo Log Capacity / Max Checkpoint Age**. The same workload reports a lower percentage on MySQL 8.0.30 and newer, so compare a server against itself over time rather than against a server on a different version.
- On MySQL 5.7 and Percona Server 5.7, the redo log checkpoint age metric is no longer exported while the server reports a placeholder value. Panels and alerts that relied on the placeholder now see a gap instead.


### Added support and deprecations

#### Native ARM64 support for PMM Server

You can now run PMM Server natively on ARM64 hosts, such as AWS Graviton instances, without x86_64 emulation. The `percona/pmm-server:3` image now includes an ARM64 build, and Docker pulls the one that matches your host automatically.

To get started, [install PMM Server with Docker](../install-pmm/install-pmm-server/deployment-options/docker/index.md) on your ARM64 host.

PMM [Apps](../apps/index.md) is only available for amd64 and cannot be deployed on ARM64 hosts.

#### Removed support for Debian 11 (Bullseye)

Debian 11 reached the end of its long-term support on 31 August 2026, so PMM Client no longer ships packages for it. Existing PMM Client installations on Debian 11 keep working, but don't receive further updates.

To keep getting PMM Client updates, upgrade the host to Debian 12 or later, then [reinstall PMM Client](../install-pmm/install-pmm-client/package_manager.md).

## 🔒 Security updates

### Grafana port 3000 bypassed nginx authentication ([PMM-15602](https://perconadev.atlassian.net/browse/PMM-15602))

Fixed an issue where Grafana was reachable on port 3000 without authentication, bypassing nginx. Grafana now only accepts connections through nginx.

### Residual security risk

PMM includes third-party components with known vulnerabilities. The server findings are based on the AMD64 Trivy report for `perconalab/pmm-server:3.10.0-rc` reviewed on October 22, 2026. The report lists 32 high-severity findings and one critical-severity finding, covering 29 unique advisory IDs. It reports no operating-system package vulnerabilities within its scan scope.

The PMM Client finding is based on the October 19, 2026 report for `perconalab/pmm-client:3.10.0-rc`. The newer server report does not establish the current status of PMM Client or the ARM64 server image.

The presence of an affected dependency does not establish that its vulnerable code path is reachable in PMM. Exposure depends on enabled features, network access, and deployment configuration. The component details and controls that follow help you assess your deployment; they do not establish that every finding is unexploitable.

#### HTTP/2 denial of service in Nomad and the ClickHouse data source ([CVE-2026-78669](https://nvd.nist.gov/vuln/detail/CVE-2026-78669))

##### Affected components

Nomad in PMM Server and PMM Client (`golang.org/x/net` v0.59.0), Grafana (`golang.org/x/net` v0.55.0), and the Grafana ClickHouse data source plugin (`golang.org/x/net` v0.58.0 and Go 1.26.5). The dependency fix is in `golang.org/x/net` v0.60.0; the Go standard library fix is in Go 1.26.9 or 1.27.2.

##### PMM-specific context

An attacker who can reach an affected HTTP/2 server can cause denial of service by sending excessive SETTINGS frames. [Nomad is disabled by default](../reference/nomad.md), and its agents on PMM Clients stop when Nomad is disabled on PMM Server. Grafana listens on loopback by default and is accessed through nginx. These controls limit exposure but do not establish whether every affected HTTP/2 code path is unreachable.

##### Mitigating factors

- Leave Nomad disabled unless you need it.
- If you enable Nomad, restrict its network access to trusted PMM nodes.
- Keep Grafana and plugin backend ports inaccessible from untrusted networks.

##### Remediation plan

Nomad, Grafana, and the ClickHouse data source plugin require dependency updates to `golang.org/x/net` v0.60.0 or later. The Go standard library fix for this HTTP/2 issue is in Go 1.26.9 or 1.27.2, but the plugin requires Go 1.26.10, 1.27.3, or later to also address the certificate validation finding described in this section. Updating Go alone does not update the separate `golang.org/x/net` dependency.

#### kin-openapi authentication bypass and denial of service

Grafana includes `github.com/getkin/kin-openapi` v0.133.0 with the following findings:

- [GHSA-r277-6w6q-xmqw](https://github.com/advisories/GHSA-r277-6w6q-xmqw): critical-severity authentication bypass when `ValidationHandler.Load()` defaults to `NoopAuthenticationFunc`; fixed in v0.144.0
- [CVE-2026-76905](https://nvd.nist.gov/vuln/detail/CVE-2026-76905): denial of service through malformed multipart request bodies; fixed in v0.141.0
- [CVE-2026-77354](https://nvd.nist.gov/vuln/detail/CVE-2026-77354): excessive resource consumption when decoding `deepObject` query parameters; fixed in v0.142.0
- [CVE-2026-100349](https://nvd.nist.gov/vuln/detail/CVE-2026-100349): nil-pointer dereference during response validation; fixed in v0.146.0
- [CVE-2026-100352](https://nvd.nist.gov/vuln/detail/CVE-2026-100352): improper handling of non-finite numeric values; fixed in v0.148.0
- [CVE-2026-100354](https://nvd.nist.gov/vuln/detail/CVE-2026-100354): unbounded recursion during schema validation; fixed in v0.149.0

##### Affected component

The Grafana binary in PMM Server.

##### PMM-specific context

These findings concern applications that use the affected OpenAPI validation functions. A dependency version match alone does not show that Grafana invokes those functions on a reachable request path. Grafana's default loopback binding prevents direct external access to port 3000, but does not replace application-level authorization.

##### Mitigating factors

- Keep Grafana behind nginx and do not override its loopback binding to expose port 3000.
- Restrict PMM access to trusted users and networks.

##### Remediation plan

Grafana requires a dependency update to `github.com/getkin/kin-openapi` v0.149.0 or later to address all six findings.

#### Compression dictionary denial of service in Grafana ([CVE-2026-63209](https://nvd.nist.gov/vuln/detail/CVE-2026-63209))

##### Affected component

The Grafana binary in PMM Server includes `github.com/klauspost/compress` v1.18.5. The fix is in v1.18.7.

##### PMM-specific context

The vulnerability can crash a process when a crafted S2 compression dictionary is passed to `s2.NewDict()` and subsequently processed by `Dict.Encode()`. The dependency version match does not establish that Grafana accepts attacker-controlled dictionaries through this code path.

##### Mitigating factors

- Restrict PMM access to trusted users and networks.
- Apply container resource limits to reduce the impact of resource-exhaustion attacks; these limits do not prevent the process crash described by this advisory.

##### Remediation plan

Grafana requires an update to `github.com/klauspost/compress` v1.18.7 or later and a rebuild. Percona builds its Grafana fork from source, so this update can be integrated and tested without waiting for an upstream Grafana binary release.

#### Other high-severity findings in Grafana dependencies

The server report lists additional high-severity findings in libraries embedded in Grafana:

- **Apache Thrift**: [CVE-2026-43871](https://nvd.nist.gov/vuln/detail/CVE-2026-43871), denial of service through an infinite loop. Installed version: v0.23.1-0.20260429145742-d2acd3c49e58; fixed in v0.24.0.
- **Grafana Tempo**: [CVE-2026-21728](https://nvd.nist.gov/vuln/detail/CVE-2026-21728), denial of service through large queries, and [CVE-2026-28377](https://nvd.nist.gov/vuln/detail/CVE-2026-28377), disclosure of an S3 encryption key through a status endpoint. Installed version: v1.5.1-0.20251027222923-cbe5f845dc7b; the listed fixes are in the Tempo 2.x series, including v2.10.3 for the disclosure.
- **Prometheus**: [CVE-2026-42151](https://nvd.nist.gov/vuln/detail/CVE-2026-42151), disclosure of an Azure OAuth client secret through the configuration API. Installed version: v0.305.3; fixed in v0.311.3.
- **Go SSH library**: [CVE-2026-56854](https://nvd.nist.gov/vuln/detail/CVE-2026-56854), authentication bypass when source-address restrictions are not enforced. Installed version: `golang.org/x/crypto` v0.52.0; fixed in v0.55.0.
- **Go DNS library**: [CVE-2026-46600](https://nvd.nist.gov/vuln/detail/CVE-2026-46600), denial of service through invalid DNS record parsing. Installed version: `golang.org/x/net` v0.55.0; fixed in v0.56.0.
- **Go text library**: [CVE-2026-56851](https://nvd.nist.gov/vuln/detail/CVE-2026-56851) and [CVE-2026-56852](https://nvd.nist.gov/vuln/detail/CVE-2026-56852), denial of service through text processing. Installed version: `golang.org/x/text` v0.37.0; fixed in v0.41.0 and v0.39.0, respectively.
- **gRPC-Go**: [GHSA-hrxh-6v49-42gf](https://github.com/advisories/GHSA-hrxh-6v49-42gf), xDS RBAC and HTTP/2 vulnerabilities; [CVE-2026-84304](https://nvd.nist.gov/vuln/detail/CVE-2026-84304), denial of service through HTTP/2 DATA frame fragmentation; and [CVE-2026-84445](https://nvd.nist.gov/vuln/detail/CVE-2026-84445), denial of service through malformed RPC requests. Installed version: v1.80.0; v1.83.2 includes the listed fixes for all three findings.

##### Affected component

The Grafana binary in PMM Server.

##### PMM-specific context

PMM uses VictoriaMetrics as its metrics backend, rather than a standalone Prometheus server. A Prometheus library finding in Grafana does not establish that the affected Prometheus configuration API is exposed. Similarly, Tempo backend, SSH server, and xDS RBAC findings require the corresponding functionality to be active and reachable. The scan does not establish those conditions.

DNS and text-processing findings require affected functions to process triggering input. Grafana's loopback binding limits direct network access, but does not establish that inputs passed through nginx cannot reach affected code.

##### Mitigating factors

- Restrict access to PMM and do not expose internal component ports.
- Review any custom Tempo, Azure OAuth, SSH, or xDS configuration against the linked advisories.
- Apply container resource limits to reduce the impact of resource-exhaustion attacks.

##### Remediation plan

Grafana requires dependency updates or compatible backports for the affected libraries. Upstream fixes are listed in the report; the affected versions remain present in this release candidate. These changes require integration and testing in Percona's Grafana build.

#### Go standard library vulnerabilities in the ClickHouse data source

The Grafana ClickHouse data source plugin is built with Go 1.26.5. The server report lists the following high-severity standard library findings:

- [CVE-2026-33818](https://nvd.nist.gov/vuln/detail/CVE-2026-33818): excessive recursion during ASN.1 decoding
- [CVE-2026-39821](https://nvd.nist.gov/vuln/detail/CVE-2026-39821): incorrect Punycode label processing
- [CVE-2026-46600](https://nvd.nist.gov/vuln/detail/CVE-2026-46600): invalid DNS record parsing
- [CVE-2026-56853](https://nvd.nist.gov/vuln/detail/CVE-2026-56853): denial of service in unencrypted HTTP/2 connections
- [CVE-2026-56858](https://nvd.nist.gov/vuln/detail/CVE-2026-56858) and [CVE-2026-56859](https://nvd.nist.gov/vuln/detail/CVE-2026-56859): cross-site scripting in HTML templates and excessive recursion during XML decoding, respectively
- [CVE-2026-56860](https://nvd.nist.gov/vuln/detail/CVE-2026-56860) and [CVE-2026-56862](https://nvd.nist.gov/vuln/detail/CVE-2026-56862): denial of service during URL path resolution and TLS KeyUpdate processing, respectively
- [CVE-2026-78667](https://nvd.nist.gov/vuln/detail/CVE-2026-78667), [CVE-2026-78669](https://nvd.nist.gov/vuln/detail/CVE-2026-78669), and [CVE-2026-97031](https://nvd.nist.gov/vuln/detail/CVE-2026-97031): denial of service through HTTP Range headers, HTTP/2 SETTINGS frames, and TLS Encrypted Client Hello processing, respectively

##### Affected component

The Grafana ClickHouse data source plugin in PMM Server.

##### PMM-specific context

The plugin queries ClickHouse on behalf of Grafana users. These findings require specific HTTP, TLS, DNS, template, or decoder code paths to process triggering input. Their presence in the plugin does not establish that every path is reachable through a PMM dashboard query.

##### Mitigating factors

- Restrict access to PMM and to data source configuration.
- Keep ClickHouse and plugin backend ports inaccessible from untrusted networks.
- Use trusted ClickHouse endpoints and retain TLS certificate verification when configuring external connections.

##### Remediation plan

The plugin requires a rebuild with Go 1.26.10, 1.27.3, or later to address the listed standard library findings and the certificate validation finding that follows. Its separate `golang.org/x/net` dependency also requires an update to v0.60.0 or later. PMM packages a prebuilt upstream plugin, so the normal update path requires a plugin release containing both changes.

#### Certificate validation in the ClickHouse data source ([CVE-2026-111943](https://nvd.nist.gov/vuln/detail/CVE-2026-111943))

##### Affected component

The Grafana ClickHouse data source plugin in PMM Server is built with Go 1.26.5. The fix is in Go 1.26.10 or 1.27.3.

##### PMM-specific context

This finding concerns specific intermediate certificates that are no longer considered trustworthy. The Go fix adds a denylist for affected certificates in `crypto/x509` verification. It is not a general bypass of all TLS certificate validation.

Exposure depends on the plugin's outbound TLS connections and trust configuration, including external ClickHouse connections. A plaintext localhost connection does not exercise this TLS verification path. The scan alone does not establish whether an affected certificate chain can be accepted in a particular deployment.

##### Mitigating factors

- Use trusted ClickHouse endpoints and retain TLS certificate verification for external connections.
- Keep the container's CA trust store current; this does not replace the Go certificate denylist fix.

##### Remediation plan

Use an upstream plugin build compiled with Go 1.26.10, 1.27.3, or later. Updating PMM's own Go binaries or the container's Go installation does not change the standard library embedded in the prebuilt plugin.

#### How to reduce risk

Until the affected components are updated:

- Restrict PMM access to trusted networks and users.
- Keep the number of PMM administrators small and enforce strong authentication.
- Leave optional services disabled unless you need them, and restrict their network access when enabled.
- Apply resource limits to PMM containers where possible.

## 🔶 Known issues

### Special characters in database passwords prevent PMM Server from starting ([PMM-15446](https://perconadev.atlassian.net/browse/PMM-15446))

PMM Server doesn't start if the password for its ClickHouse, PostgreSQL, or VictoriaMetrics database contains `%`. The VictoriaMetrics password also can't contain `!`, `*`, or `'`. This mainly affects PMM HA Cluster and deployments with external databases, where you set these passwords yourself.

Use only letters and numbers in these passwords. The PMM admin password is not affected.
