# Percona Monitoring and Management 3.10.0

**Release date**: 30 August 2026

Percona Monitoring and Management (PMM) is an open source database monitoring, management, and observability solution for MySQL, PostgreSQL, MongoDB, Valkey and Redis. PMM empowers you to:

- monitor the health and performance of your database systems
- identify patterns and trends in database behavior
- diagnose and resolve issues faster with actionable insights
- manage databases across on-premises, cloud, and hybrid environments

## Release summary

### MongoDB Unused Indexes dashboard

You can now spot unused MongoDB indexes directly in PMM, without running manual queries against each node. Go to **Dashboards > MongoDB > MongoDB Unused Indexes** to see indexes with zero accesses since the last `mongod` restart, along with access trends and a least-used index ranking to help you prioritize cleanup.

Built on the existing [MongoDB Unused Indexes advisor check](../advisors/checks/mongodb-unused-indexes.md), the dashboard adds a filterable view across clusters, replica sets, nodes, and databases, so you safely identify and remove indexes that add write overhead and consume memory without benefiting reads.

Requires the `indexstats` collector on the MongoDB exporter. See [MongoDB Unused Indexes](../reference/dashboards/dashboard-mongodb-unused-indexes.md).

### Environment filter for MySQL Replication Summary

The [MySQL Replication Summary](../reference/dashboards/dashboard-mysql-replication-summary.md) dashboard now includes an **Environment** filter, consistent with other PMM dashboards. Use it to quickly narrow replication data to a specific environment when working with a large number of replication sets across multiple environments.

![Environment filter on MySQL Replication Summary dashboard](../images/env_filter.png)

### PMM HA Cluster is now generally available

PMM HA Cluster is now production-ready, so your monitoring and alerting stay online when a PMM node fails. PMM 3.10.0 builds on the Tech Preview from PMM 3.6.0 and adds what you need to run HA in production:

- Support for OpenShift 4.18 to 4.21, including ROSA with hosted control planes, alongside Amazon EKS 1.33 to 1.35.
- [Upgrades to new PMM releases](../pmm-upgrade/upgrade_helm_ha.md) with `helm upgrade`.
- Backup and restore for the full HA installation, including VictoriaMetrics and ClickHouse data.
- [Built-in alert rules](../alert/templates_list.md#built-in-ha-alert-rules) for no active leader, split-brain, leader flapping, unreachable nodes, and quorum at risk. PMM creates them automatically, so you only need to configure a [contact point](../alert/contact_points.md).
- An improved [PMM HA Health Overview](../reference/dashboards/dashboard-ha-health-overview.md) dashboard, with an overall health score, per-component status tables showing leader and primary roles, and resource usage panels. You can now open it from **PMM HA > Overview** in the side menu.
- Scaling to 1, 3, or 5 PMM Server replicas, with Helm validation that rejects even counts.
- Deployment into multiple namespaces on the same cluster.

The HA status badge in the side menu now reflects the actual cluster state, and the **Inventory** page lists HA services in a dedicated section. To keep the cluster consistent, you can no longer delete PMM Server nodes from **Inventory**.

![PMM HA leader badge showing the current leader and Healthy status](../images/pmm-ha-leader-badge.png)

The VictoriaMetrics, ClickHouse, and PostgreSQL operators are upgraded to their latest versions, including Percona Operator for PostgreSQL 3.0.0.

For help with lost Raft quorum, leader election problems, and component logs, see [Troubleshoot PMM HA Cluster issues](../troubleshoot/ha_issues.md).

## 📈 Improvements

- [PMM-15071](https://perconadev.atlassian.net/browse/PMM-15071): Added the [MongoDB Unused Indexes](../reference/dashboards/dashboard-mongodb-unused-indexes.md) dashboard for identifying indexes with zero accesses since the last `mongod` restart. Requires the `indexstats` collector.

- [PMM-15104](https://perconadev.atlassian.net/browse/PMM-15104): The **Queries** panel on the **PostgreSQL Instance Overview** dashboard now surfaces the worst-performing queries immediately, without paging through thousands of timestamp-sorted rows. Queries are aggregated over the selected time range, capped at 500, and sorted by average execution time. The panel has been renamed to **Top slow queries** to reflect this, and includes new columns for when a query peaked, how many times it ran, and its average execution time per call.

- [PMM-15189](https://perconadev.atlassian.net/browse/PMM-15189): Added documentation for starting and stopping Real-Time Analytics (RTA) on MongoDB services from the command line. See [pmm-admin inventory add agent rta-mongodb-agent](../use/commands/pmm-admin/inventory.md#pmm-admin-inventory-add-agent-rta-mongodb-agent) and [pmm-admin inventory remove agent](../use/commands/pmm-admin/inventory.md#pmm-admin-inventory-remove-agent).

- [PMM-13932](https://perconadev.atlassian.net/browse/PMM-13932): Added an **Environment** filter to the [MySQL Replication Summary](../reference/dashboards/dashboard-mysql-replication-summary.md) dashboard to quickly narrow replication data to a specific environment.

- [PMM-14848](https://perconadev.atlassian.net/browse/PMM-14848): Your query text filter and page size in **Query Analytics > Real-Time** now survive page refreshes, so you no longer lose your view when the page reloads. When sharing a link with a teammate, they now also land on the same query text filter and page size you had set, not just the same cluster or service.

- [PMM-14735](https://perconadev.atlassian.net/browse/PMM-14735) / [PMM-15445](https://perconadev.atlassian.net/browse/PMM-15445): PMM HA Cluster deployments can now be upgraded to new PMM releases using `helm upgrade`. Fixed a `pmm-token-init` Job immutability error that prevented upgrades on existing clusters. See [Upgrade PMM HA Cluster using Helm](../pmm-upgrade/upgrade_helm_ha.md).

- [PMM-10785](https://perconadev.atlassian.net/browse/PMM-10785): Alert evaluation in PMM HA Cluster now continues when an individual PMM node fails, so alert coverage is maintained during failovers and rolling upgrades.

- [PMM-13860](https://perconadev.atlassian.net/browse/PMM-13860): Added the [PMM HA Health Overview](../reference/dashboards/dashboard-ha-health-overview.md) dashboard, providing a central view of HA cluster health with component health status, pod counts and restarts, resource usage, storage usage, and service availability timeline.

- [PMM-14731](https://perconadev.atlassian.net/browse/PMM-14731): Raft consensus metrics are now exposed for PMM HA Cluster, with built-in Prometheus alerting rules for quorum loss and other HA failure scenarios.

- [PMM-14956](https://perconadev.atlassian.net/browse/PMM-14956): PMM now ships two sets of built-in alert rules that it creates and maintains automatically. On every PMM Server: four component health rules for ClickHouse, Grafana, VictoriaMetrics, and the Query Analytics API. On HA Cluster deployments: five HA rules covering no active leader, split-brain, leader flapping, node unreachable, and quorum at risk. See [Built-in alert templates](../alert/templates_list.md).

- [PMM-14979](https://perconadev.atlassian.net/browse/PMM-14979): Encryption keys are now shared across all PMM nodes in an HA cluster, ensuring consistent encryption across the three replicas.

- [PMM-15149](https://perconadev.atlassian.net/browse/PMM-15149): PMM HA Cluster can now be deployed in any Kubernetes namespace, removing the previous restriction to the `pmm` namespace.

- [PMM-14754](https://perconadev.atlassian.net/browse/PMM-14754): PMM inventory nodes in an HA cluster are now protected from accidental deletion.

- [PMM-15462](https://perconadev.atlassian.net/browse/PMM-15462): The VictoriaMetrics, ClickHouse, and PostgreSQL operators used by PMM HA Cluster have been upgraded to their latest versions.

- [PMM-14738](https://perconadev.atlassian.net/browse/PMM-14738): PMM HA Cluster now supports scaling to 1, 3, or 5 PMM Server replicas. The Helm chart now validates that replica counts are odd (required for Raft quorum) and rejects even values at install and upgrade time.

## ✅ Fixed issues

- [PMM-15067](https://perconadev.atlassian.net/browse/PMM-15067): Fixed an issue where the **Alerts** entry was missing from the left navigation for anonymous users when Grafana anonymous access was enabled, although you could still access the page via direct URL.

- [PMM-15092](https://perconadev.atlassian.net/browse/PMM-15092): Fixed the **InnoDB Row Reads** panel in the [MySQL InnoDB Details](../reference/dashboards/dashboard-mysql-innodb-details.md) dashboard where the series name in the legend appeared blank. The series now correctly shows as **Rows**.

- [PMM-15204](https://perconadev.atlassian.net/browse/PMM-15204): The CSV export in **Query Analytics > Real-Time** now includes all available query data fields instead of a fixed set of columns, including two new ones in this release: `service_id` and `query_text`. Your exports will always reflect the latest query fields available in your PMM version.

- [PMM-14908](https://perconadev.atlassian.net/browse/PMM-14908): Fixed the **Replication Delay Details** section of the [MySQL Group Replication Summary](../reference/dashboards/dashboard-mysql-group-replication-summary.md) dashboard incorrectly including asynchronous replication nodes in mixed replication environments, making it harder to identify actual Group Replication lag. The section now shows only Group Replication nodes, giving you a clean view of replication delay without noise from unrelated nodes.

- [PMM-15091](https://perconadev.atlassian.net/browse/PMM-15091): Fixed the **Total Performance** panels in the [Disk Details](../reference/dashboards/dashboard-disk-details.md) dashboard showing approximately twice the actual IOPS and throughput on hosts using Linux software RAID. If your dashboards showed inflated disk performance figures on RAID hosts, they will now report accurate values.

- [PMM-15302](https://perconadev.atlassian.net/browse/PMM-15302): Fixed the **SSH key** tab incorrectly showing in **Configuration > Settings** on non-AMI deployments. The tab now appears only on AWS AMI. On other deployment types, configure SSH access directly on the host or container. See [SSH key](../install-pmm/install-pmm-server/deployment-options/virtual/ssh.md).

- [PMM-14734](https://perconadev.atlassian.net/browse/PMM-14734) / [PMM-15420](https://perconadev.atlassian.net/browse/PMM-15420): Fixed the PMM HA status badge always showing **Healthy** even when follower or leader pods were deleted or not ready. The badge now accurately reflects the actual cluster state.

- [PMM-14678](https://perconadev.atlassian.net/browse/PMM-14678): Fixed database dashboards not showing metrics for services added to PMM HA Cluster via `pmm-admin`. Dashboards now work correctly regardless of how the service was registered.

- [PMM-14665](https://perconadev.atlassian.net/browse/PMM-14665): Fixed the node list when adding a service to PMM HA Cluster incorrectly including PostgreSQL database instance nodes alongside PMM HA nodes. The list now shows only the expected PMM HA nodes.

- [PMM-15394](https://perconadev.atlassian.net/browse/PMM-15394) / [PMM-15393](https://perconadev.atlassian.net/browse/PMM-15393) / [PMM-15395](https://perconadev.atlassian.net/browse/PMM-15395): Fixed several HAProxy routing issues in PMM HA Cluster deployments.

- [PMM-14680](https://perconadev.atlassian.net/browse/PMM-14680): Fixed PostgreSQL database instance nodes and services in PMM HA Cluster displaying with an incorrect `pmm-` prefix in their names.

- [PMM-14787](https://perconadev.atlassian.net/browse/PMM-14787): Fixed data retention settings having no effect in PMM HA Cluster. Changing the retention period under **Configuration > Settings > Advanced Settings** now correctly applies to metrics storage.

- [PMM-15426](https://perconadev.atlassian.net/browse/PMM-15426): Fixed PMM HA Cluster failing to install on OpenShift due to SCC-rejected pods, HAProxy DNS resolver misconfiguration, and privileged port binding. PMM HA Cluster can now be deployed on OpenShift 4.21+ (including ROSA HCP).

- [PMM-15565](https://perconadev.atlassian.net/browse/PMM-15565): Fixed PMM HA Cluster upgrades failing on OpenShift.

- [PMM-15487](https://perconadev.atlassian.net/browse/PMM-15487): Fixed PMM HA leader pods whose Grafana process has died continuing to receive all UI traffic and returning 502 errors. The pod is now restarted automatically, restoring UI availability without manual intervention.

- [PMM-15461](https://perconadev.atlassian.net/browse/PMM-15461): Fixed database queries and connections panels failing to load under high load in PMM HA Cluster, caused by misaligned vmselect and vmauth settings.

- [PMM-15556](https://perconadev.atlassian.net/browse/PMM-15556): Fixed alert rules failing to load in PMM HA Cluster due to Grafana's rules API not being routed through vmauth.

- [PMM-15400](https://perconadev.atlassian.net/browse/PMM-15400): Fixed Grafana's admin password not being set on fresh PMM HA installations using the default `secret.create: false` path. Previously, Grafana kept the default `admin/admin` credentials and the `pmm-token-init` job failed with 401.

- [PMM-15501](https://perconadev.atlassian.net/browse/PMM-15501): Fixed fresh installation of PMM HA failing when `secret.create: true` is set. A Helm template was rendering a secret lookup before the creation hook ran; passwords are now generated consistently across all templates.

- [PMM-15304](https://perconadev.atlassian.net/browse/PMM-15304): PMM Server nodes in PMM HA Cluster are now registered as **Container** type in Inventory instead of **Generic**. This applies to new registrations; existing deployments keep their current node type.
