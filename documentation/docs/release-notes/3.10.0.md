# Percona Monitoring and Management 3.10.0
**Release date**: TBD

Percona Monitoring and Management (PMM) is an open source database monitoring, management, and observability solution for MySQL, PostgreSQL, MongoDB, Valkey and Redis. PMM empowers you to:

- monitor the health and performance of your database systems
- identify patterns and trends in database behavior
- diagnose and resolve issues faster with actionable insights
- manage databases across on-premises, cloud, and hybrid environments

## 📋 Release summary


### PMM HA Cluster is now generally available

PMM 3.10.0 completes the HA Tech Preview introduced in PMM 3.6.0 with the features and improvements needed to run HA reliably in production:

- OpenShift support for versions 4.18 to 4.21, including ROSA with hosted control planes, alongside Amazon EKS 1.33 to 1.35.
- In-place [upgrades to new PMM releases](../pmm-upgrade/upgrade_helm_ha.md) with a single `helm upgrade` command. PMM Server replicas restart one at a time, so monitoring is only briefly interrupted while a new leader takes over.
- [Backup and restore](../install-pmm/backup-restore-HA-clustered.md) for your entire HA installation to S3-compatible storage or a shared volume, on demand or on a schedule. Restore into the same cluster or a new namespace for disaster recovery.
- [Built-in alert rules](../alert/templates_list.md#pmm_ha_alerts) for no active leader, split-brain, leader flapping, unreachable nodes, and quorum at risk, created automatically. Configure a [contact point](../alert/contact_points.md) to receive notifications.
- Improved [PMM HA Health Overview](../reference/dashboards/dashboard-ha-health-overview.md) dashboard with alive and expected instance counts, leader and primary roles, and resource usage panels, accessible from **PMM HA > Overview** in the side menu. To see the current leader, go to **PMM HA > Identify Nodes**.
- [Flexible scaling](../install-pmm/install-HA-clustered.md#scale-pmm-server-replicas) to 1, 3, or 5 PMM Server replicas, with Helm validation that rejects even counts.
- [Multi-namespace deployments](../install-pmm/install-HA-clustered.md#install-pmm-ha-into-multiple-namespaces) on the same cluster.

- Multiple [fixes](#fixed-issues-ha) and [improvements](#improvements-ha) for HA Cluster, including an HA status badge that now reflects the actual cluster state.

![PMM HA badge showing Healthy status, with the Overview and Identify Nodes menu items](../images/HA-Status.png)

For help with lost Raft quorum, leader election problems, and component logs, see [Troubleshoot PMM HA Cluster issues](../troubleshoot/ha_issues.md).

### Built-in alerts for PMM's own components

PMM now monitors its own components and alerts you when one stops responding, so you can fix it before you lose monitoring data. Four [built-in alert rules](../alert/templates_list.md#pmm_component_alerts) warn you when:

- **VictoriaMetrics** components fail, to avoid gaps in your metrics
- **ClickHouse** is down, to protect your Query Analytics (QAN) data
- **Grafana** instances fail in a PMM HA Cluster, to keep your dashboards available
- **Query Analytics API** is down, to make sure QAN stays up-to-date

The new rules are turned on automatically on every PMM Server, including when you upgrade. 

To get notified, configure a [contact point](../alert/contact_points.md). To customize the rules or turn them off, see [Manage the built-in alert rules](../alert/built_in_alerts.md).

### MongoDB Unused Indexes dashboard

You can now spot unused MongoDB indexes directly in PMM, without running manual queries against each node. Go to **Dashboards > MongoDB > MongoDB Unused Indexes** to see indexes with zero accesses since the last `mongod` restart, along with access trends and a least-used index ranking to help you prioritize cleanup.

Built on the existing [MongoDB Unused Indexes advisor check](../advisors/checks/mongodb-unused-indexes.md), the dashboard adds a filterable view across clusters, replica sets, nodes, and databases, so you safely identify and remove indexes that add write overhead and consume memory without benefiting reads.

Requires the `indexstats` collector on the MongoDB exporter. See [MongoDB Unused Indexes](../reference/dashboards/dashboard-mongodb-unused-indexes.md).

### MySQL 9.7 support and monitoring improvements

PMM 3.10 adds support for Oracle MySQL 9.7 and Percona Server 9.7 with changes that also improve MySQL 8.0 and newer monitoring:

- **Service Summary reports** now work on MySQL 9.x hosts where `mysqldump` is not installed.
- **InnoDB redo log panels** in [MySQL InnoDB Details](../reference/dashboards/dashboard-mysql-innodb-details.md) now render correctly across all supported MySQL versions. **Total Log Space**, **InnoDB Logging Performance**, **InnoDB Log File Usage Hourly**, **InnoDB Log File Size** and **InnoDB Log Files** were previously always empty on MySQL 5.7, Percona Server 5.7 and MariaDB, and now show data there.
- The [InnoDB redo log sizing advisor](../advisors/checks/innodb_redo_logs_not_sized_correctly.md) now correctly evaluates redo log capacity on MySQL 8.0.30 and newer.
- **Backups of MySQL 9.7** are no longer rejected with an incompatible-XtraBackup error. Use a Percona XtraBackup release from the same series as your server, for example PXB 9.7.x for MySQL 9.7.x.
- **Top Tables by Rows Read** and **Top Tables by Rows Changed** in [MySQL Table Details](../reference/dashboards/dashboard-mysql-table-details.md) now show data on Community MySQL, which does not provide the user statistics these panels previously required. Both still need per-table statistics collection, which PMM disables for services with more tables than the configured limit.
- **AHI Miss Ratio** in [MySQL InnoDB Details](../reference/dashboards/dashboard-mysql-innodb-details.md) showed the hit ratio instead of the miss ratio on short time ranges. It now matches **InnoDB AHI Miss Ratio**.
- **Query Cache panels** across [MySQL Instances Overview](../reference/dashboards/dashboard-mysql-instances-overview.md) and [MySQL Instance Summary](../reference/dashboards/dashboard-mysql-instance-summary.md) now show a notice on MySQL 8.0 and newer instead of silently showing no data.

#### Changes to be aware of

- The Checkpoint Age limit series is now labelled **Redo Log Capacity / Max Checkpoint Age**. On MySQL 8.0.30 and newer the checkpoint age is measured against the total redo log capacity, while older servers expose only the smaller synchronous flush threshold. The same workload therefore reports a lower percentage on 8.0.30 and newer, so compare a server against itself over time rather than against a server on a different version.
- On MySQL 5.7 and Percona Server 5.7, `mysql_info_schema_innodb_metrics_recovery_log_lsn_checkpoint_age` is no longer exported while the server reports the `-1` placeholder for that row. Previously the placeholder was exported as a gauge with the value `-1`. Panels and alerts that treated `-1` as a reading now see a gap instead.


### Override alert thresholds for individual nodes

If you have the PMM **Admin** role, you can now set a custom alert threshold for a specific node without editing the alert rule or creating a new one. One rule still covers all nodes, but each node can use its own sensitivity. A node with an override uses its own threshold, and the others keep the rule's default.

Templates that support overrides show a **Dynamic** badge in **Alerts > Templates**. Currently, only the built-in [Node high CPU load](../alert/templates_list.md#os_alerts) template supports this, but you can add override support to your own custom templates. More built-in templates will support overrides in future releases.

To get started, see [Override alert thresholds for individual nodes](../alert/alert-thresholds.md).

### Environment filter for MySQL Replication Summary

The [MySQL Replication Summary](../reference/dashboards/dashboard-mysql-replication-summary.md) dashboard now includes an **Environment** filter, consistent with other PMM dashboards. Use it to quickly narrow replication data to a specific environment when working with a large number of replication sets across multiple environments.

![Environment filter on MySQL Replication Summary dashboard](../images/env_filter.png)

### Added support and deprecations

#### Native ARM64 support for PMM Server

You can now run PMM Server natively on ARM64 hosts, such as AWS Graviton instances, without x86_64 emulation. The `percona/pmm-server:3` image now includes an ARM64 build, and Docker pulls the one that matches your host automatically.

To get started, [install PMM Server with Docker](../install-pmm/install-pmm-server/deployment-options/docker/index.md) on your ARM64 host.

#### Removed support for Debian 11 (Bullseye)

Debian 11 reached the end of its long-term support on 31 August 2026, so PMM Client no longer ships packages for it. Existing PMM Client installations on Debian 11 keep working, but don't receive further updates.

To keep getting PMM Client updates, upgrade the host to Debian 12 or later, then [reinstall PMM Client](../install-pmm/install-pmm-client/package_manager.md).

## 🔶 Known issues

### Special characters in database passwords prevent PMM Server from starting

- [PMM-15446](https://perconadev.atlassian.net/browse/PMM-15446): PMM Server doesn't start if the password for its ClickHouse, PostgreSQL, or VictoriaMetrics database contains `%`. The VictoriaMetrics password also can't contain `!`, `*`, or `'`. This mainly affects PMM HA Cluster and deployments with external databases, where you set these passwords yourself.
