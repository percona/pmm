PMM 3.10.0 introduces its first database management apps, letting you run operations like MySQL backups and diagnostics directly from PMM. With this, two new API services give you programmatic access to those operations: the Tasks API for triggering and monitoring runs, and the Inventory API for querying the hosts and services those operations run on.

## New features

### Apps API (Technical Preview)

PMM 3.10.0 expands beyond monitoring with its first database management apps. The Apps API gives you programmatic access to the same operations available in the PMM UI under **Apps**: running MySQL backups, sending diagnostic data to your Percona support case, and more.

The API consists of two services:

- **SEP Tasks API**: trigger operations, monitor runs, stream logs, manage schedules, and check connectivity.
- **SEP Inventory API**: query the nodes, services, schemas, and tables that SEP syncs from your PMM inventory.

#### New endpoints

##### Tasks

- `POST /execute/{task_name}`: trigger a task on a target host
- `GET /{task}/history/`: list execution history for a task
- `GET /history/{task_history_id}/logs/`: stream logs for a run
- `POST /history/{task_history_id}/stop/`: stop a running task
- `GET /{task_name}/periodic/`: list schedules for a task
- `POST /{task_name}/periodic/`: create a recurring schedule
- `POST /connectivity-check/`: verify that an executor host can reach a database before running a task
- `GET /hosts/`: list available executor hosts

##### Inventory

- `GET /nodes/`: list nodes (hosts) synced from PMM
- `GET /services/`: list database services synced from PMM
- `GET /services/{service_id}/schemas/`: list schemas within a service
- `GET /schemas/{schema_id}/tables/`: list tables within a schema
- `GET /summary/`: count of all inventory entities

#### Common use cases

- **Automated backups**: trigger MySQL backups on a schedule or on demand, monitor run status, and retrieve logs programmatically.
- **Pre-flight checks**: verify host-to-database connectivity before dispatching a task.
- **Inventory queries**: look up node and service IDs to use as parameters in task execution requests.
- **CI/CD integration**: chain tasks and check their outcomes as part of automated database workflows.

#### Requirements and limitations

##### Requirements

To use the Apps API, you need:

- PMM Server 3.10.0 or later
- PMM Client 3.10.0 or later with the Nomad client enabled
- Nomad enabled on PMM Server (`PMM_ENABLE_NOMAD=1` and `PMM_PUBLIC_ADDRESS` set)

##### Limitations

As a first release, the Apps API has the following constraints:

- **Technical Preview**: not recommended for production use yet.
- The `meta` field keys accepted by each task depend on the specific task template. See the [task documentation](#) for the keys each operation supports.
