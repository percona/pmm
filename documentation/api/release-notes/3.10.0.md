PMM 3.10.0 adds database management apps and per-target alert threshold overrides to the API.

## New features

### Apps API (Technical Preview)

PMM 3.10.0 expands beyond monitoring with its first database management apps. The Apps API gives you programmatic access to the same operations available in the PMM UI under **Apps**: running MySQL backups, sending diagnostic data to your Percona support case, and more.

The API consists of two services:

- **PMM Extensions Tasks API**: trigger operations, monitor runs, stream logs, manage schedules, and check connectivity.
- **PMM Extensions Inventory API**: query the nodes, services, schemas, and tables that PMM Extensions syncs from your PMM inventory.

#### New endpoints

##### Tasks

- `POST /extensions/api/apps/{app_key}/{task_name}/execute`: run a task on its configured execution host
- `GET /extensions/api/extensions/task-history/`: list execution history
- `POST /extensions/api/extensions/task-history/{id}/stop/`: stop a running task
- `GET /extensions/api/extensions/task-stats/{task_name}`: aggregate run statistics for a task
- `GET /extensions/api/extensions/periodic-tasks/`: list recurring schedules
- `POST /extensions/api/extensions/periodic-tasks/{task_name}/`: create a recurring schedule
- `PUT /extensions/api/extensions/periodic-tasks/{id}`: update a schedule
- `DELETE /extensions/api/extensions/periodic-tasks/{id}`: delete a schedule
- `GET /extensions/stream-logs/{id}`: stream task logs as server-sent events

##### Inventory

- `GET /extensions/api/extensions/hosts/`: list executor hosts available for task execution
- `GET /extensions/api/extensions/services/`: list database services synced from PMM
- `GET /extensions/api/extensions/services/{id}/schemas`: list schemas within a service
- `GET /extensions/api/extensions/schemas/{id}/tables`: list tables within a schema

#### Common use cases

- **Automated backups**: trigger MySQL backups on a schedule or on demand, monitor run status, and retrieve logs programmatically.
- **Pre-flight checks**: verify host-to-database connectivity before dispatching a task.
- **Inventory queries**: look up node and service IDs to use as parameters in task execution requests.
- **CI/CD integration**: chain tasks and check their outcomes as part of automated database workflows.

#### Requirements and limitations

##### Requirements

To use the Apps API, you need:

- PMM Server 3.10.0 or later
- PMM Client 3.10.0 or later with the Nomad client enabled
- Nomad enabled on PMM Server (`PMM_ENABLE_NOMAD=1` and `PMM_PUBLIC_ADDRESS` set)

##### Limitations

As a first release, the Apps API has the following constraints:

- **Technical Preview**: not recommended for production use yet.
- The execute request body is the same for every task: `eta`, `chain_task_names`, and `chain_on_failure`.

### Override alert thresholds for individual nodes via API

PMM 3.10.0 lets you set a different alert threshold for individual nodes without editing the rule or creating a separate one. A single rule can now apply different sensitivity per node: the threshold you set for a specific node applies only there, and the rest keep the rule's default.

Templates that support this show a **Dynamic** badge in **Alerts > Templates**. You can manage overrides from the [PMM UI](https://docs.percona.com/percona-monitoring-and-management/3/alert/alert-thresholds.html) or programmatically using the following endpoints:

#### New endpoints

- `GET /v1/alerting/thresholds`: list the threshold each overridable parameter is currently evaluated against, and whether the value comes from an override or the rule's default.
- `POST /v1/alerting/thresholds`: set a threshold override for one parameter of one rule on one target.
- `POST /v1/alerting/thresholds:clear`: remove an override and return the target to the rule's default.
- `POST /v1/alerting/thresholds:batchUpdate`: apply several set and clear operations in a single transaction.

#### Requirements and limitations

To use the threshold endpoints, you need:

- An [Admin-role token](ref:authentication). Viewer and editor tokens are rejected with `403`.
- Percona Alerting enabled in **Configuration > Settings > Advanced Settings**
- A rule from a **Dynamic** template. When you create one, the response includes a `rule_id` for use with these endpoints. Find **Dynamic** templates in **Alerts > Templates**. If your rule was created before PMM 3.10.0, [enable overrides for older rules](ref:pmm-alert-threshold-overrides#enable-overrides-for-older-rules).
- Node scope (`THRESHOLD_SCOPE_NODE`) for the target. Service and cluster scopes are accepted by the schema but return `501 Not Implemented`.
