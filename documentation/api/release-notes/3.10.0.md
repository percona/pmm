PMM 3.10.0 adds per-target alert threshold overrides to the alerting API.

## New features


### Override alert thresholds for individual nodes via API

PMM 3.10.0 lets you set a different alert threshold for individual nodes without editing the rule or creating a separate one. A single rule can now apply different sensitivity per node: the threshold you set for a specific node applies only there, and the rest keep the rule's default. 

Templates that support this show a **Dynamic** badge in **Alerts > Templates**. You can manage overrides from the [PMM UI](https://docs.percona.com/percona-monitoring-and-management/3/alert/alert-thresholds.html) or programmatically using the following endpoints:

#### New endpoints

- `GET /v1/alerting/thresholds`: list the threshold each overridable parameter is currently evaluated against, and whether the value comes from an override or the rule's default.
- `POST /v1/alerting/thresholds`: set a threshold override for one parameter of one rule on one target.
- `POST /v1/alerting/thresholds:clear`: remove an override and return the target to the rule's default.
- `POST /v1/alerting/thresholds:batchUpdate`: apply several set and clear operations in a single transaction.

#### Requirements and limitations

To use the threshold endpoints, you need:

- An [Admin-role token](ref:authentication). Viewer and editor tokens are rejected with `403`.
- Percona Alerting enabled in **Configuration > Settings > Advanced Settings**
- A rule from a **Dynamic** template. When you create one, the response includes a `rule_id` for use with these endpoints. Find **Dynamic** templates in **Alerts > Templates**. If your rule was created before PMM 3.10.0, [enable overrides for older rules](ref:pmm-alert-threshold-overrides#enable-overrides-for-older-rules).
- Node scope (`THRESHOLD_SCOPE_NODE`) for the target. Service and cluster scopes are accepted by the schema but return `501 Not Implemented`.
