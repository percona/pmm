PMM 3.11.0 includes API changes that can affect your scripts and integrations. Check each change before you upgrade.

## Breaking changes

### Access roles apply to service account tokens on Query Analytics and metrics query APIs

With access control enabled, the Query Analytics and VictoriaMetrics query APIs now filter the data that a service account token reads by the access roles of its service account, as they do for a user. A service account with no role gets the default role when one of its tokens first calls these APIs. In PMM 3.8.0 to 3.10.0, these tokens could read all the data.

#### Affected endpoints

- `/v1/qan/*` and `/v1/qan:*`: Query Analytics
- `/prometheus/api/v1/*`: VictoriaMetrics queries

Metric ingestion through `/victoriametrics/api/v1/write` isn't affected.

#### Impact

If your automation reads these APIs with a service account token, assign its service account the access roles it needs before you upgrade. Without access control, service account tokens keep working on these APIs as before.

### Requests without credentials refused

If Grafana anonymous access is enabled (`GF_AUTH_ANONYMOUS_ENABLED=true`), PMM API requests without credentials return `401` with `Unauthorized`. Starting with PMM 3.8.0, these requests got Viewer access, for example to `/v1/users`, `/v1/server/settings/readonly`, Query Analytics and `/v1/actions`.

The health checks `/v1/server/readyz`, `/v1/server/leaderHealthCheck` and `/ping` still answer without credentials, and so does Grafana's own API for anonymous visitors.

#### Impact

If your scripts call the PMM API without credentials, authenticate them with a service account token or a user account.
