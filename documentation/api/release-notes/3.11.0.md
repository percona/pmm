PMM 3.11.0 adds MySQL support to the Real-time Analytics (RTA) API.

## New features

### Real-time Analytics API for MySQL

In addition to MongoDB, the RTA API now works with MySQL, Percona Server for MySQL and MariaDB services, through the same endpoints.

For MySQL, the responses also include lock information, so when a table seems frozen, you can find the statements waiting for a lock and the transaction that holds it.

#### Changed endpoints

- `GET /v1/realtimeanalytics/services`: accepts `SERVICE_TYPE_MYSQL_SERVICE` as a `service_type` filter and returns a new `mysql` array next to `mongodb`.
- `POST /v1/realtimeanalytics/sessions:start`: starts sessions for MySQL services. The response includes the new `service_type` and `status_message` fields.
- `GET /v1/realtimeanalytics/sessions`: lists MySQL sessions with `service_type` and `status_message`. `status_message` explains why a session is in `SESSION_STATUS_ERROR`, or which data a running session can't collect, as found when it started.
- `POST /v1/realtimeanalytics/queries:search`: returns MySQL queries with a new `my_sql_payload`. It includes the connection details, row counts, full scan and lock time, and lock information in `blocked_status`, `blocked_by`, `lock_type`, `locked_table`, `locked_index` and `requested_lock_mode`.
- `POST /v1/inventory/agents` and `PUT /v1/inventory/agents/{agent_id}`: accept the new `rta_mysql_agent` agent type.
- `GET /v1/inventory/agents` and `GET /v1/inventory/agents/{agent_id}`: return `rta_mysql_agent` agents. `GET /v1/inventory/agents` also accepts `AGENT_TYPE_RTA_MYSQL_AGENT` as an `agent_type` filter.

#### Behavior changes

- `POST /v1/inventory/agents`: a new `rta_mongodb_agent` is now rejected with HTTP 400 (`FAILED_PRECONDITION`) when the pmm-agent is older than 3.7.0, the first version that supports RTA for MongoDB.

#### Common use cases

- **Lock contention**: find statements waiting for a lock and the transaction at the head of the chain, so you can end it.
- **Incident response**: see which statements are running on a slow MySQL server, and who sent them.
- **Query efficiency**: spot statements that examine many rows or scan a full table while they're still running.

#### Requirements and limitations

##### Requirements

To use the RTA API with MySQL services, you need:

- PMM Server 3.11.0 or later
- PMM Client 3.11.0 or later on the database host
- `performance_schema` enabled on the MySQL server
- The PMM database user with the `SELECT` privilege. To get lock information, it also needs `PROCESS`.

##### Limitations

- MariaDB turns off some Performance Schema settings by default, so row counts, full scan, lock time and metadata lock details can be missing. On MySQL 5.7, only metadata lock details are missing. A missing value means RTA couldn't measure it, not that it's zero.
- MySQL 5.7 and MariaDB report lock modes less precisely, so you can't always tell record locks apart from gap locks.
- Managed services such as Amazon RDS for MySQL haven't been tested with RTA.
